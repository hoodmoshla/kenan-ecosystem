# بناء KenanWallet على Android

المشروع يستخدم Kotlin وJetpack Compose وMaterial 3، مع اتجاه RTL. تم التحقق من بناء نسخة debug في بيئة التطوير عبر Gradle Wrapper 8.9 وJDK 21 وAndroid SDK 34:

```bash
cd android-app
./gradlew :app:assembleDebug
```

ينتج الملف `app/build/outputs/apk/debug/app-debug.apk`. هذه نسخة تطوير موقعة بشهادة Android debug القياسية، وليست APK إصدار نهائي. لا تستخدم شهادة debug كتوقيع إصدار أو كأساس لتحديثات مستقبلية. لم يُثبّت الملف على هاتف أو محاكي في هذه الجلسة لعدم وجود جهاز متصل.

## اتصال الشبكة التجريبية

شغّل العقدة على المضيف:

```bash
python3 -m blockchain.node_server --port 8545 --data data/chain.json
```

من محاكي Android يصل التطبيق إلى المضيف عبر `http://10.0.2.2:8545`. يسمح Manifest الخاص بنسخة debug باتصال HTTP لتجربة العقدة المحلية فقط؛ يبقى `usesCleartextTraffic=false` في Manifest الأساسي، ولذلك لا يُعد هذا إعدادًا مناسبًا للإنتاج. على جهاز فعلي، لا توصل التطبيق بعقدة عبر شبكة غير موثوقة، ولا تغيّر إعداد release إلى HTTP.

عميل `NodeApi` ينقل طلبات RPC إلى `Dispatchers.IO` ويتحقق من شكل عنوان Kenan قبل القراءة. بُني هذا المصدر بنجاح، لكن لم يُختبر الاتصال من محاكي/هاتف فعلي؛ اختبارات HTTP في Python تثبت مسار العقدة والـBackend، لا واجهة Android نفسها.

## ما يزال مطلوبًا قبل أي إصدار للمستخدمين

إنشاء المحفظة واستعادتها وربطها بـAndroid Keystore غير منفذتين في واجهة التطبيق. زر الإرسال لا يوقّع أو يرسل معاملة من Android، والاستقبال لا يعرض QR. التداول والمساعد شاشتان توضيحيتان فقط. يلزم أيضًا اختبار على أجهزة فعلية، مراجعة الوصولية والشاشات الصغيرة، اختبار اتصال HTTPS إنتاجي، وتوقيع Release بالمفتاح الصحيح للمشروع بعد التحقق من بصمته. لا يوجد مفتاح إصدار موثق لهذا المستودع، لذلك لم يُنتج Release APK.
